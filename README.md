# GFSupport

Операционная система поддержки и продаж Delever: приём сообщений из Telegram
и WhatsApp, тикеты, аналитика (FRT/SLA/загрузка), собственная CRM продаж,
онбординг брендов, ИИ-разбор и два десятка фоновых задач.

Один разработчик, один деплой: фронт и API живут в этом репозитории
и выкладываются на Vercel (регион `fra1`, база Neon там же).

## Запуск

```bash
npm install
vercel env pull .env.local   # переменные окружения из прода
npm run dev                  # фронт на vite, API проксируется
```

Проверки перед пушем — обе, у API отдельный tsconfig и фронтовая сборка его не видит:

```bash
npm run typecheck:api
npm run build
```

## Где что лежит

| Путь | Что это |
|---|---|
| `api/support/` | Все серверные функции. `_lib/` — общее ядро, `webhook/` — входы внешних систем, `cron/` — фоновые задачи |
| `src/` | React-приложение, feature-sliced: `pages` → `features` → `entities` → `shared` |
| `whatsapp-bridge/` | Отдельный сервис на Baileys (Railway) — единственная часть вне Vercel |
| `scripts/db-schema.mjs` | Генератор справочника схемы из боевой базы |
| `DATABASE_SCHEMA.md` | Сгенерированный справочник: все таблицы, колонки, связи. Не править руками |
| `CLAUDE.md` | Неочевидные правила и грабли — прочитать до первой правки |
| `vercel.json` | Расписание всех фоновых задач |

## Внешние системы

Neon (единственное хранилище), три Telegram-бота, WhatsApp-мост, OpenAI,
Meta (лид-формы + директ + комментарии), AmoCRM (временный мост на период
ухода), Vercel Blob, Google Docs (договоры), Click (платежи), ПланФакт
(сверка оплат). Все ключи — в env Vercel; локально ничего не хранится.

## Схема базы

~150 таблиц. DDL исторически разбросан по коду (`CREATE TABLE IF NOT EXISTS`
в обработчиках), поэтому единственный честный источник — сама база:

```bash
node scripts/db-schema.mjs   # перегенерирует DATABASE_SCHEMA.md
```

Запускать после каждой миграции; скрипт только читает.
